## New ideas raised, with my opinion — not yet implemented

16. **Filter Statcast pulls to symmetric-ish parks for outfield-dependent stats, pull from all parks for infield stats.** **Agree, worth doing.** This matters more than just distance: a park's fence position changes which *result category* a given EV/LA combo lands in at all (a ball that's a Fenway single off the Monster is a homer or a routine fly out almost everywhere else), so asymmetric parks bias `la_ideal`/`ev_min`/`ev_max` too, not only `depth_min`/`depth_max` — this directly matches our own uniform-fence assumption, so restricting `fly_ball`/`line_drive`/`home_run`/`2B`/`3B` pulls to a curated "reasonably symmetric" park list makes the derived ranges more internally consistent with our game's own physics. Caveats: no MLB park is perfectly symmetric, so the park list is a judgment call (not a clean filter field in the data), and it shrinks the sample for already-thin results (triples, line drives) further — grounder/bunt/infield_single/popup stats should still pull from every park, since infield dimensions are standardized by rule. Needs a curated team/park list before it can run.
